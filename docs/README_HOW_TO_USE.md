# 📖 README 작성 가이드 - 사용법

## 🎯 3단계로 완성하기

### 1단계: 질문에 답변하기 (30분)
```bash
README_QUESTIONS.md 파일 열기
→ 각 질문에 본인의 답변 작성
→ 솔직하고 구체적으로!
```

### 2단계: 템플릿에 넣기 (20분)
```bash
README_TEMPLATE.md 파일 열기
→ [여기에 작성] 부분 찾기
→ 1단계에서 작성한 답변 복사/붙여넣기
→ 표현 자연스럽게 다듬기
```

### 3단계: 최종 검토 (10분)
```bash
- 맞춤법 확인
- 링크 작동 확인
- 스크린샷 추가 (선택사항)
→ README.md로 저장!
```

## 📝 구체적 예시

### ❌ Before (AI 느낌)
```markdown
## 프로젝트 목적
본 프로젝트는 최신 테스트 자동화 기술을 활용하여
엔터프라이즈급 품질 보증 시스템을 구축하는 것을 목표로 합니다.
```

### ✅ After (사람 느낌)
```markdown
## 프로젝트 목적
QA 엔지니어로 취업하기 위해 만든 포트폴리오 프로젝트입니다.
처음엔 Selenium으로 시작했는데, Playwright가 더 빠르고
자동 대기 기능이 편하다는 걸 알고 새로 배웠습니다.
실제 운영 중인 사이트(마켓컬리)를 테스트하면서
실무에서 마주칠 문제들을 미리 경험하고 싶었습니다.
```

## ⚠️ 주의사항

### 절대 하지 말 것:
1. ❌ **거짓말 쓰기**
   - "500개 테스트 케이스 작성" (실제론 15개)
   - "대규모 프로덕션 환경 적용" (개인 프로젝트인데)

2. ❌ **과장된 표현**
   - "혁신적인", "최첨단", "엔터프라이즈급"
   - "획기적인 성능 향상"

3. ❌ **AI가 쓴 티나는 문장**
   - "본 프로젝트는...", "...을 목표로 합니다"
   - "향후 지속적으로...", "...에 기여하고자 합니다"

### 꼭 포함할 것:
1. ✅ **본인만의 경험**
   - 어떤 문제를 겪었고 어떻게 해결했는지
   - 왜 그런 선택을 했는지

2. ✅ **구체적인 숫자**
   - "15개 테스트 케이스"
   - "8시간마다 자동 실행"
   - "응답 시간 3초 이내"

3. ✅ **솔직한 한계**
   - "현재 Chromium만 지원"
   - "일부 테스트 POM 적용 중"
   - "Captcha 있는 페이지는 제외"

## 💬 예시 답변 (참고용)

### Q4. 가장 어려웠던 문제
```
[문제]
GitHub Actions에서 환경변수가 로드되지 않아
TMDB API 테스트가 계속 실패했습니다.

[원인]
로컬에서는 .env 파일을 읽었지만,
CI 환경에서는 GitHub Secrets에 등록만 하고
YAML에서 env로 전달하지 않았습니다.

[해결]
playwright-test.yaml 파일의 env 섹션에
TMDB_API_KEY: ${{ secrets.API_KEY_PLAYWRIGHT }}
형태로 명시적으로 전달했습니다.

[배움]
로컬 환경과 CI 환경은 다르다는 것을 체감했고,
환경변수 관리의 중요성을 배웠습니다.
공식 문서를 꼼꼼히 읽는 습관이 생겼습니다.
```
